# Contributing

Thanks for contributing! Keep changes focused, documented, and easy to review.

## Workflow
1. Fork or branch from `main`.
2. Make one focused change.
3. Run the project's local checks from the README.
4. Update documentation when behavior changes.
5. Open a pull request with a clear summary and testing notes.

## Standards
- Prefer small, reviewable commits.
- Never commit secrets, credentials, generated databases, or local state.
- Preserve backward compatibility unless the change is explicitly breaking.
